# 密码本云同步设计

- 日期：2026-11-10
- 分支：`feat/nsh`
- 前置：`2026-11-09-password-vault-design.md`（本地密码本）
- 状态：已实现；2026-11-14 部署到家里 PVE 的 LXC 容器（Debian 13）。同日把网络从 Tailscale 改为域名 + HTTPS + DDNS（用户反馈 Tailscale 每台设备都要装、不方便），步骤见 `server/deploy/README.md`

## 1. 目标

把密码本同步到用户自己的服务器（家里 PVE 上的一个 LXC 容器），多台设备之间实时同步。要求：

- **零知识**：服务器（或拿到服务器数据的人）得不到任何明文，也无法离线猜出主密码。
- 解密所需的主密码由用户输入，不保存在任何地方；秘密密钥只保存在用户自己的设备钥匙串和用户手里的恢复信息中。
- 服务器不能悄悄删除、回滚或替换记录而不被发现。

不做：浏览器扩展、多用户共享、Web 端、二维码配对、移动端。

## 2. 用户确认的决定

| 问题 | 决定 |
|---|---|
| 秘密密钥（两把钥匙派生） | 要 |
| 网络 | 域名 + HTTPS（Caddy，Let's Encrypt 证书走阿里云 DNS 验证）+ DDNS（A 记录为家里公网 IPv4，AAAA 为容器自己的 IPv6）；路由器转发 IPv4、放行 IPv6 的同一个非 80/443 端口；同步服务器只监听 127.0.0.1 |
| 代码位置 | 本仓库（公开）：`server/` 与 `crates/sync-proto/`；地址、令牌等一律不进仓库 |
| 部署 | 已部署到 PVE 上的 LXC（2026-11-14） |

## 3. 安全设计

### 3.1 密钥（相对本地密码本的变化）

```
秘密密钥 SK：128 位随机数，形如 CX-XXXXX-XXXXX-XXXXX-XXXXX-XXXXX-X（Base32，含校验字符）
KEK = Argon2id(主密码, salt, secret = SK, m=64MiB, t=3, p=1)     ← 只有同时拥有两者才能得到
DEK（不变）由 KEK 包装，条目由 DEK 加密
```

- 启用同步时生成 SK，用 KEK(主密码, SK) 重新包装 DEK，`vault_meta.version` 记为 2（1 = 只用主密码）。条目不用重新加密。
- SK 存入本机钥匙串（不经 Touch ID，像 1Password 一样只存在设备上），并**只显示一次**给用户抄写或保存；用户必须输入其中最后一组字符确认已保存，才能完成启用。
- 新设备首次解锁时需要输入 SK，然后存入该设备的钥匙串。
- 修改主密码沿用现有做法（更换 DEK、重新加密全部条目），SK 不变。
- 服务器数据被拿走：没有 SK 就无法尝试主密码，离线暴力破解不可行。

### 3.2 记录与认证

- 每条记录有修订号 `revision`。加密的附加认证数据（AAD）为 `"{id}:{revision}"`，防止用旧版本冒充新版本。
  - 旧数据 `revision = 0`，AAD 仍为 `id`；启用同步时全部重新加密为修订号 1。
- 删除保留一条**删除标记**（也加密、也带修订号），用于同步删除。
- **清单（manifest）**：所有记录 `(id, revision, deleted)` 加上递增的 `version`，整体用 DEK 加密（AAD 固定）。服务器只能原样保存，无法伪造。
  - 拉取时：清单必须能解密，`version` 不得小于本机已见过的版本，服务器返回的每条记录必须与清单中的 `(id, revision)` 一致，应用后本机的全部记录必须与清单完全一致。任一不满足：拒绝这次同步，提示"同步数据异常"，本机数据不变。

### 3.3 登录与设备

- 设备令牌：32 字节随机数，`Authorization: Bearer`。服务器只存 SHA-256。令牌存本机钥匙串。
- 首台设备：服务器在没有任何设备时启动，会在日志里打印一次性**管理码**（10 分钟有效，错 5 次作废），用它注册第一台设备。
- 之后的设备：已登录设备生成**配对码**（10 分钟有效，一次性，错 5 次作废）。
- 设置里可以查看设备列表、吊销任意设备（吊销本机则退出同步）。
- 令牌与加密密钥完全无关：令牌泄露只能读写密文。

### 3.4 网络

- 同步服务器只监听 `127.0.0.1:8787`，同机的 Caddy 在域名上提供 HTTPS 并反向代理，应用层再加令牌。Caddy 同时用阿里云 DNS API 维护 A、AAAA 记录（DDNS）；路由器过滤 AAAA 时，容器改用公共 DNS 才能查到自己的 IPv6。
- 客户端只允许任意 `https://`，以及本机的 `http://`（`localhost`、`127.0.0.0/8`、`[::1]`，测试和隧道用）；其他明文地址拒绝。证书按系统根证书（webpki）校验。

## 4. 同步

### 4.1 服务器接口（`/v1`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/bootstrap` | `{admin_code, device_name}` → `{device_id, token}`（仅在没有设备时可用） |
| POST | `/pair` | 已登录：生成配对码 `{code, expires_at}` |
| POST | `/join` | `{code, device_name}` → `{device_id, token}` |
| GET / DELETE | `/devices`、`/devices/{id}` | 设备列表 / 吊销 |
| GET / PUT | `/vault` | 密码本头（version、kdf、salt、wrapped_dek、key_check）与清单；PUT 带 `base` 版本号，冲突返回 409 |
| GET | `/changes?since=seq` | 序号大于 `since` 的记录（每个 id 只返回最新版）与当前 `seq` |
| POST | `/changes` | 上传记录：每条带 `base_revision`；服务器端修订号与之不符则该条进入 `conflicts`，其余写入并分配新序号 |
| GET | `/events` | WebSocket：有新序号时推送 `{"seq": n}` |

### 4.2 客户端流程

- **只在密码本解锁时同步**（校验清单需要 DEK）；解锁后立即同步一次。
- 本地保存或删除：修订号 +1，标记为待上传，立即触发同步。
- 一次同步：
  1. 拉取头部。头部版本比本机新（别的设备改了主密码）：替换本机头部、锁定密码本，提示用新主密码解锁。
  2. 拉取变更并按 3.2 校验后应用。
  3. 上传待上传记录。冲突的条目：以服务器版本为准，本机的那一版另存为一条新记录，名称后加"（冲突副本）"，由用户决定保留哪个。
  4. 上传新清单（`base` 冲突则回到第 2 步，最多 3 次）。
- 实时：后台线程保持 WebSocket 连接，收到序号后同步；断线时每 30 秒轮询一次，并以指数退避重连。

### 4.3 启用与加入

- **启用（第一台设备）**：填服务器地址和管理码 → 生成 SK（显示一次并确认）→ 重新包装 DEK → 记录重新加密为修订号 1 → 上传头部、全部记录、清单。
- **加入（其他设备）**：填服务器地址和配对码 → 下载头部 → 输入主密码和 SK 解锁 → 下载全部记录。
  - 加入时本机的密码本必须为空或未设置，否则提示先导出备份再重置（第一版不做两个已有密码本的合并）。

## 5. 服务端实现

- `server/`：Rust 二进制 `clipboardx-sync-server`（axum + tokio + rusqlite），单个 SQLite 文件。
- 配置通过命令行或环境变量：`--listen 100.x.y.z:8787 --data /var/lib/clipboardx-sync`。
- `crates/sync-proto/`：客户端与服务端共用的请求和响应类型。
- 部署：`server/deploy/` 下提供 systemd 单元、Caddy 配置与构建脚本、安装脚本与说明（LXC + Caddy）。
- CI：额外编译 Linux x86_64 版服务端，发布时作为附件。

## 6. 公开仓库

- 服务器地址、令牌、管理码不进仓库：地址存在本机设置，令牌和 SK 存在钥匙串，服务端配置用环境变量。仓库只放示例。
- CI 加入 gitleaks 扫描。

## 7. 测试

- **服务端**：接口测试覆盖认证、管理码与配对码（过期、次数）、修订号冲突、`since` 查询、吊销后令牌失效、头部版本冲突。
- **客户端加密**：SK 编码与校验、v1→v2 升级、没有 SK 无法解锁、AAD 带修订号。
- **端到端**：测试里启动真实服务器和两个客户端服务，覆盖增、改、删、冲突副本、主密码修改传播、新设备加入。
- **篡改**：服务器回滚清单、删除记录、替换为旧修订号、伪造删除标记——客户端都必须拒绝且本机数据不变。
- **扫描**：服务器数据库中搜索不到任何明文和 SK。

## 8. 安全审查后的修订（2026-11-10）

- **头部不再直接替换**：服务器上的新头部先单独暂存（`vault_sync.staged_header`），本机原有头部保持不变。只有用户输入的新主密码确实能用它解出数据密钥、并通过 key_check 校验后，才替换本机头部。暂存期间旧主密码仍能打开本机密码本。
- **头部认证**：修改主密码的设备上传新头部时，同时附上"新头部摘要用旧数据密钥加密"的认证值（`auth`）。版本号恰好加一的头部必须带有效认证值，否则拒绝（Tampered）。跨越多个版本的头部无法校验，只暂存，等用户解锁时再判断。头部的 KDF 参数、格式、盐长度和包装密钥长度都有上下限，越界直接拒绝，不会尝试派生密钥。
- **采用新主密码时保留本机修改**：解锁状态下发现新头部时，提示输入新主密码（`adopt_staged_header`）。本机尚未上传的修改会从旧密钥重新加密到新密钥。如果用户选择锁定后再用新主密码解锁，就无法拿到旧密钥，这些修改会留在本机且不会上传（不会污染服务器）。
- **启用秘密密钥时更换数据密钥**：旧备份里只受主密码保护的数据密钥，打不开任何同步的数据。
- **清单绑定内容**：每条记录除修订号外，还记录 `SHA-256(nonce‖ciphertext)`。同一修订号的另一份密文会被拒绝。
- **不信任服务器给的计数**：
  - `last_seq` 取收到的记录中最大的序号；
  - 清单版本号只在本机确认后才记下，数值运算全部检查溢出；
  - 校验失败时自动从头完整拉取一次，再判断数据是否真的被篡改。
- **拒绝修订号 0**：修订号为 0 的记录只靠 id 认证，不接受来自服务器的这类记录。
- **网络**：HTTP 客户端不跟随重定向，应答大小上限 64 MB；WebSocket 被服务器关闭后间隔重连。
- **服务器**：
  - 连续 5 次错码后进入 60 秒冷却，不再作废用户已发出的码；
  - 同时有效的配对码最多 5 个；
  - systemd 增加系统调用过滤和 IP 白名单（tailnet 与本机）；
  - 安装脚本升级时会重启服务；
  - 发布附带 SHA-256 校验文件。

## 9. 限制

- 主密码或 SK 任一丢失，且没有其他已解锁设备时，数据无法恢复。
- 服务器能看到记录数量、大小与修改时间。
- 只在密码本解锁时同步；锁定期间的远端改动在下次解锁时同步。
- 设备令牌泄露后，持有者读不到任何明文，但可以覆盖或损坏服务器上的密文（服务器不保留历史），使同步中断；本机数据不受影响。应及时吊销该设备，并定期备份服务器数据库。
- 新设备加入时没有可比对的信任锚：服务器可以给新设备提供旧的快照（无法伪造内容）。
- 服务暴露在公网：管理码和配对码 40 位、10 分钟有效、一次性，连续输错全局冷却（攻击者可借此暂时阻止配对，但拿不到令牌）。阿里云 AccessKey 存在容器里（0600，RAM 子账号只给解析权限）。泄露后，持有者能改解析、给域名签证书，从而截获设备令牌；令牌只能读写密文（见上一条），读不到明文。发现泄露时在 RAM 控制台禁用并更换，再吊销设备。
